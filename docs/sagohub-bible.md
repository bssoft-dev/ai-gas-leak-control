## 🌌 The Vision: SagoHub (싱크씽크)

> **"Why we build."** (우리의 철학이자 궁극적 목표)

### 정의

SagoHub는 인간과 소프트웨어의 **공진화(Co-evolution)**를 지향하는 사상(Philosophy)이자 기술적 비전입니다.

### 핵심 가치

#### 1. Sync (동기화)
- 기계적 오류와 사용자의 의도 불일치를 해소
- 사용자의 의도와 시스템의 동작이 완벽하게 일치하는 상태

#### 2. Twin (복제)
- 사용자의 패턴과 사고방식을 학습하여 디지털 분신 형성
- 사용자만의 고유한 사고 패턴을 이해하고 반영

#### 3. Evolution (진화)
- 단순 도구를 넘어, 사용자의 인지 능력을 확장하는 파트너
- 사용자와 함께 성장하고 진화하는 시스템

### 슬로건

**"Think in Sync."**

## 📦 The Product: Foldering (폴더링)

> **"What users see."** (사용자가 만나는 제품)

### 정의

SagoHub 철학을 구현한 **첫 번째 상용 소프트웨어**입니다.

### 형태

겉보기엔 **"파일 정리 유틸리티"**지만, 내부는 **"맥락 인식 AI 엔진"**인 트로이의 목마입니다.

### 특징

#### Non-intrusive (비침투적)
- 사용자의 기존 파일 시스템(폴더, 탐색기)을 그대로 사용
- 기존 워크플로우를 방해하지 않음

#### Headless (헤드리스)
- 별도의 앱을 켜지 않아도, 파일만 넣으면 작동
- 백그라운드에서 조용히 동작

#### Secure (안전)
- 모든 데이터는 로컬(Docker)에 안전하게 격리
- 사용자의 프라이버시 보호

### 슬로건

**"Stop organizing. Start foldering."**

## ⚙️ The Platform: Foldering Engine (엔진)

> **"How it works."** (제품을 구동하는 OS)

### 정의

Docker 컨테이너 기반으로 동작하는 **마이크로 OS (Operating System)**입니다.

### 역할

#### Host Interface
- 사용자 PC(Electron UI)와 통신
- 설정 및 상태 동기화

#### Sandbox
- `Service`들이 사용자 PC를 망가뜨리지 않도록 격리
- 안전한 실행 환경 제공

#### Reaction Core
- 파일 이벤트를 감지하고 적절한 `Service`를 깨워서 실행
- 이벤트 기반 반응형 아키텍처

#### Resource Manager
- CPU/RAM 사용량을 조절하며 AI 모델 로드/언로드
- 효율적인 리소스 관리

## 🧩 The Unit: Service (서비스)

> **"What developers make."** (기능의 최소 단위)

### 정의

엔진 위에서 돌아가는 **독립적인 앱(App)**입니다. (기존의 '파이프라인'을 포함하는 상위 개념)

### 구조 (Package)

하나의 폴더 안에 다음 요소들이 캡슐화됩니다:

1. **Metadata:** 이름, 버전, 아이콘 (`service.yaml`)
2. **Config:** 사용자에게 보여줄 설정 UI 스키마
3. **Logic (Pipelines):** `Event` -> `Action`으로 이어지는 반응 회로
4. **Assets:** 프롬프트 파일, 커스텀 파이썬 스크립트 등

### 예시

- `회의록 비서` - 회의록을 분석하여 요약 및 액션 아이템 추출
- `영수증 정리기` - 영수증을 카테고리별로 자동 분류
- `일기장 봇` - 일기 내용을 분석하여 감정 및 패턴 추출

## 🎬 사용자 시나리오로 보는 개념 연결

1. **SagoHub (철학):** 개발팀은 "사용자의 뇌를 확장하자"는 비전을 가지고...
2. **Foldering (제품):** 깔끔한 파일 정리 앱을 출시했습니다.
3. **Service (단위):** 사용자는 앱 내 스토어에서 **"스마트 회의록 비서"** 서비스를 설치(ON)합니다.
4. **Engine (플랫폼):** 사용자가 파일을 저장하는 순간, 엔진이 **"회의록 비서 서비스"**를 깨워서 파일을 분석하게 하고, 결과를 정리해 줍니다.

## 🏗️ 전체 아키텍처

```
┌─────────────────────────────────────────────────┐
│ Level 1: Philosophy (SagoHub)                │
│ "Think in Sync." - 인간과 AI의 공진화           │
└─────────────────────────────────────────────────┘
                    ↓ Inspires
┌─────────────────────────────────────────────────┐
│ Level 2: Product (Foldering)                   │
│ Desktop App (Electron) - 사용자 인터페이스     │
└─────────────────────────────────────────────────┘
                    ↓ Controls
┌─────────────────────────────────────────────────┐
│ Level 3: Platform (Foldering Engine)           │
│ Docker Core - SagoHub, 리소스 관리          │
└─────────────────────────────────────────────────┘
                    ↓ Executes
┌─────────────────────────────────────────────────┐
│ Level 4: Unit (Services)                        │
│ Meeting Assistant, Receipt Organizer, etc.     │
└─────────────────────────────────────────────────┘
```

이 4가지 개념이 명확히 분리됨으로써, 우리는 **거대한 비전(SagoHub)**을 잃지 않으면서도 **구체적인 상품(Foldering)**을 팔 수 있고, **확장 가능한 생태계(Services)**를 구축할 수 있게 되었습니다.
